# ImageSitter 决策记录

## 产品方向（Product Direction）

- **目标用户**：游戏辅助 / 桌面自动化脚本开发者。
- **未解决的 job**：在固定窗口的固定位置，为一个"有多种形态、带蒙版/过渡色/透明度变化"的动态对象，快速定义可被脚本直接消费的像素特征签名，并随画面迭代持续校准。
- **直接竞品与替代**：
  - 按键精灵类找色工具：单点找色、无语义分组、无校准闭环；
  - OpenCV 模板匹配 / 相似度算法：对透明蒙版、过渡帧、形态切换不稳健，且卷积开销不满足游戏时效；
  - 通用截图标注工具：只标注，不产出机器可执行特征。
- **差异化**：
  1. 多特征组 OR 匹配——一个对象多种形态，每组对应一种形态；
  2. 逐点 RGB 容差 + alpha 两种语义（忽略/参与比对），正面处理蒙版、过渡色、显隐；
  3. 排除点（mustNot）区分相似对象；
  4. 采样校准：采集多形态样本自动推导参考色与容差（学习能力的基础形态）；
  5. winsitter 后台捕获：不抢前台、不要求窗口可见；
  6. 导出 JSON 规范 + 参考实现，脚本零成本集成。
- **结论**：立项。MVP 闭环 = 定义 → 校准 → 验证 → 导出。

## Build vs Reuse

| 能力 | 决策 | 理由 |
| --- | --- | --- |
| 窗口发现 / 绑定 / 后台取帧 | 复用 winsitter（运行时加载预编译 winsitter.dll，C ABI） | 同团队 SDK，已验证 GPU 捕获与后台语义；DLL 直连避免源码编译及其 vendor 补丁链 |
| 特征匹配引擎 | 自研（`src-tauri/src/domain/engine.rs`） | 无现成库覆盖"多点签名 + 容差 + 排除点"语义；逐点采样 O(点数) 满足实时性 |
| 校准统计 | 自研（`src-tauri/src/domain/calibrate.rs`） | min/max 区间推导，逻辑轻量且是产品核心 |
| PNG 编码 | `image` crate，仅预览路径 | 匹配热路径直接操作 RGBA，不编解码 |
| UI 组件 | shadcn-vue（源码进项目维护，reka-ui 内核） | 用户指定；源码维护便于定制像素级工具界面 |

## 框架选择

用户指定 Tauri 2 + Rust + Vue 3 + TypeScript + Vite + Tailwind CSS 4。
窗口默认 1280×800，最小 960×600（客户区），无边框窗口 + UI 自绘标题栏。

## 已知边界与发布条件

- 匹配仍是稀疏逐点特征；对大幅旋转、透视变形或全局光照改变，应使用块统计或专用视觉模型。
- 坐标缩放是宽高独立线性变换，不处理应用自身重新排版导致的控件迁移；此时应选锚点模式或重建规则。
- winsitter 为专有 SDK；公开仓库不包含 DLL，对外分发安装包前必须确认 DLL 分发许可。
- 自动更新依赖 HTTPS 更新端点和 Tauri 更新签名密钥；Windows SmartScreen 信任依赖代码签名证书。两者均是发布方外部资料，不存入源码。
